cfPROXYIP / WORKER PROBE

把探针部署到你的 Cloudflare

先生成密钥，再选择仓库一键部署或控制台粘贴。最后把 Worker 地址和同一密钥填入本地项目。

本页可直接双击打开。密钥只保存在当前页面，刷新后清除；生成链接不会附带密钥。

1. 准备探针密钥

生成 64 位十六进制随机值。Cloudflare 的 PROBE_TOKEN 和本地 CFPROXY_WORKER_TOKEN 必须一致。密钥请自行保管，不要提交到仓库。

2A. 从公开仓库一键部署

把 worker 目录的内容上传为独立的 GitHub/GitLab 公开仓库，再填入仓库地址。也可以上传整个项目，然后填入 worker 子目录的网页地址。

完整项目示例：https://github.com/用户名/仓库/tree/main/worker。这里生成链接，不验证仓库是否存在或是否公开。

尚未填写仓库地址；暂未上传可用下方控制台方法。

Deploy to Cloudflare ↗

点击后登录 Cloudflare，按页面连接 GitHub/GitLab、选择 Worker 名称，并将第 1 步的密钥填入 PROBE_TOKEN。Cloudflare 会在你的 Git 账号创建仓库副本并部署 Worker。

将部署按钮加入仓库 README

2B. 尚无仓库：控制台粘贴部署

  1. 打开 Cloudflare Workers & Pages，选择 Create application → Start with Hello World，取名并部署。
  2. 进入 Worker 的 Settings → Runtime，兼容日期设为 2026-11-01，保留/添加 nodejs_compat 兼容标志。此日期已默认启用 Node 兼容，显式标志与项目配置一致。
  3. 打开 dist/index.js 单文件，复制全部内容，在 Worker 的 Edit code 中替换默认代码，点击 Deploy。
  4. Settings → Variables and Secrets → Add，类型选 Secret，名称 PROBE_TOKEN，值填第 1 步的密钥，再部署。
  5. 复制 Settings → Domains & Routes 中的 https://…workers.dev 地址。根路径返回 404 属于正常行为，探针由本地项目调用。

如果控制台入口名称改变或没有在线编辑选项，按 部署文档 使用 Wrangler。粘贴的是 dist/index.js，不是需要本地模块的 src/index.js。

3. 连接本地项目

默认隐藏配置中的密钥；“复制后端配置”会复制真实密钥。只修改这两项，保留 .env 里其他配置。地址不带 /probe、查询参数或密钥。

  1. 保存 .env，停止原 Python 服务，再运行 python -m cfproxy。Docker 使用 docker compose up -d --force-recreate 重新读取环境。
  2. 刷新管理页面，选择 Workers 路径，先勾选 1–3 个候选，每目标采样 1 次，并发 1，开始检测。
  3. 在详情里查看 Worker 机房、TLS/HTTP 成败和观测出口地区。要找日本出口，选择“观测出口 → 日本 JP”；候选归属本身不保证出口位于日本。

Workers 模式变为可选，只表示本地配置完整。实际检测通过才说明此次 Worker 路径可用。Cloudflare 自有 IP 段受出站 TCP 限制。
